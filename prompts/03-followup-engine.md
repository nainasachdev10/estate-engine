# Prompt 03 — Follow-up Engine (WhatsApp + Email, Claude-personalised)

> Run after Prompt 02. This module turns a qualified lead into a site visit through multi-touch nurture, with every message rewritten by Claude per lead.

---

## Task

Build the WhatsApp + email drip system. AiSensy for WhatsApp, Brevo for email. Every message is generated by Claude personalised on: lead name, language preference, location, source, project, objections from the call, and what stage of the drip they're in.

Read `CLAUDE.md`. Stay in the existing structure.

### 1. Messaging package

Create `packages/messaging/src/`:

- `aisensy.ts` — wraps AiSensy's API. Exports:
  - `sendTemplate({ phone, templateName, params, mediaUrl? })` — for the **first message in the 24hr window** (must be a Meta-approved template)
  - `sendFreeForm({ phone, body, mediaUrl? })` — only callable if the lead has replied in last 24 hours (we track this from incoming webhooks)
  - `handleIncoming(payload)` — webhook handler, marks lead as `replied`, opens the 24hr window in DB
- `brevo.ts` — wraps Brevo's transactional email API. Exports:
  - `sendEmail({ to, subject, htmlBody, fromName? })`
  - `handleWebhook(payload)` — tracks delivered/opened/bounced into the `messages` table

Both record every send into the `messages` table with provider IDs for de-duplication.

### 2. The drip sequences

Define 3 drips as data, not code, in `packages/messaging/src/sequences.ts`:

```typescript
export const SEQUENCES = {
  qualified_warm: [  // qualified on call, positive sentiment
    { delay_minutes: 5,    channel: 'whatsapp', kind: 'brochure_send' },
    { delay_minutes: 60,   channel: 'whatsapp', kind: 'site_visit_nudge' },
    { delay_minutes: 1440, channel: 'email',    kind: 'developer_credibility' },
    { delay_minutes: 2880, channel: 'whatsapp', kind: 'social_proof' },
    { delay_minutes: 5760, channel: 'whatsapp', kind: 'urgency_inventory' },
    { delay_minutes: 10080,channel: 'email',    kind: 'last_chance' }, // 7 days
  ],
  callback_requested: [
    { delay_minutes: 10,   channel: 'whatsapp', kind: 'confirm_callback_time' },
    // Then re-enters voice queue at the requested time
  ],
  no_answer: [
    { delay_minutes: 5,    channel: 'whatsapp', kind: 'gentle_intro' },
    { delay_minutes: 1440, channel: 'whatsapp', kind: 'value_prop' },
    { delay_minutes: 4320, channel: 'email',    kind: 'final_followup' },
  ],
  // Add not_qualified → drop to long-term newsletter, monthly
};
```

Each `kind` maps to a **Claude prompt** that generates the actual message body. Define those prompts in `packages/content/src/messages/` (one file per kind). Each prompt takes lead+project+call_summary+objections and returns a JSON `{ subject?, body, suggested_send_time_ist? }`.

### 3. Inngest functions

- `lead.qualified` → enters lead into `qualified_warm` sequence
- `lead.no_answer_final` → enters into `no_answer` sequence
- `sequence.send_step` (cron-like, runs every 5 min) → finds messages due to send, generates content with Claude, sends via the right channel, schedules next step

For WhatsApp specifically: if the lead hasn't replied yet AND we're outside 24hr window, the message MUST use an approved template. Maintain a `templates` table in Supabase listing approved template names + their variable signatures.

### 4. Templates we need pre-approved in AiSensy/Meta

Write `docs/whatsapp-templates.md` listing the templates I need to submit for approval, in Meta's required format:

- `lead_intro` — "Namaste {{1}}, {{2}} here from {{3}}. Aapne {{4}} ke baare mein enquire kiya tha. Bohot dhanyavaad! Kya main aapko quick brochure bhej sakti hu? — *Reply 'YES' for brochure*"
- `brochure_followup` — sends after they reply YES
- `site_visit_invite` — "Hi {{1}}, kya aap iss weekend {{2}} site visit ke liye available hain? {{3}} ke ground floor pe ek brand new model flat tayyar hai."
- ... 4 more

Each template entry includes: name, category (UTILITY/MARKETING), language (en/hi), placeholders, sample, expected approval time.

### 5. Inbound handling

When the lead replies on WhatsApp:
1. Webhook → store the message
2. Open 24hr free-form window in `leads.whatsapp_window_open_until`
3. Cancel any pending templated sends in the queue (move to free-form)
4. Run Claude to classify intent: `interested / objection / out_of_market / asking_question / spam`
5. If `asking_question` → auto-reply with Claude-generated answer from project FAQ (stored in `projects.faq` jsonb)
6. If `interested` → notify the assigned human via a Slack webhook (configurable per client) and pause the drip
7. Update lead `status` and `score` accordingly

### 6. Email design

Use a single base HTML template `packages/content/src/email-template.html` with: client logo, dark luxury theme matching dashboard, gold CTA button. Claude writes only the body copy and subject; the template wraps it.

### 7. Dashboard additions

Add `/leads/[id]` page showing the full conversation timeline: every call (with transcript collapsible), every message (with status badges), every status change. Make it look like a chat UI. Add a "Pause sequence" / "Resume" / "Skip to step N" admin controls.

### 8. Failsafes

- Rate limit per phone: max 1 WhatsApp/day, max 2 emails/day
- Quiet hours: no sends between 9pm and 9am IST
- Global kill switch: env var `MESSAGING_ENABLED=true|false`
- Per-client kill switch: `clients.messaging_paused boolean`
- Sanity check: before every send, Claude reviews the generated message with a 1-line prompt "Does this message follow Indian real estate etiquette and avoid making promises? Return YES or a 5-word fix." If not YES, skip + log to events.
